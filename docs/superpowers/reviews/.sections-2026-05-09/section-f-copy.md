## Findings

### Critical
- **Slideshow fallback bodies are kid-deck for every audience** — `functions/api/slideshow.js:124,128,130,132` — `'Look. Say the word.'` / `'Listen. Repeat. Try.'` / `'What did we learn?\nHomework: write 3 sentences.'` — these are the hard-coded fallback bodies for `warmup`, `core`, and `wrapup` slides. An `adult` or `exam_prep` audience whose Sonnet call fails gets a deck that reads like a year-3 phonics lesson. Fix: branch the body strings by audience. Suggested copy below for adult: warmup `'Two-minute warmup: name three nouns from last lesson.'`, core `'New structure. Watch the modelled example, then try one with your tutor.'`, wrapup `'Recap. Take one structure home — write three sentences.'` Exam prep gets crisper still.

- **Country-binding caption renders awkward sentences** — `src/lib/page-rates.js:38` (and the same code in `page-tax.js`, `page-setup.js`, `page-insurance.js`, `page-payments.js`) — `'Showing ' + (document.title.split('—')[0] || 'data ').trim() + ' for '` produces text like *"Showing Hourly rate calculator for United Kingdom Change"* — the page title is the WHOLE H1 phrase, not a topic noun. The intent (per the spec) was `"Showing tax info for United Kingdom"`. Fix: either hard-code a topic per page (`const TOPIC = 'tax info';`) or change the script to read a `data-caption-topic` attribute on the page, e.g. `<body data-caption-topic="tax info">`. Until fixed, the caption is broken English on every country-bound page.

### Important
- **Source-language help reads stilted next to symmetric target help** — `lesson-plan.html:127,134` — target says `"Pick the language being taught."` (imperative, peer voice), source says `"The language the student already speaks."` (declarative noun phrase, no verb). Mixing imperative + declarative in adjacent help spans is a small voice slip. Fix: `"Pick the language the student already speaks."` to match the parallel verb structure.

- **Same "Pick the language being taught." string in 4 files** — `cefr.html:140`, `worksheet.html:128`, `lesson-plan.html:127`, `marking.html:127` — flagged in 2026-05-08 review and still un-deduplicated. Now down to 4 words from 26 (the trim happened) so the urgency is lower, but for a tutor jumping between three tools in one session the literal repetition still reads canned. Optional fix: vary one or two — worksheet could say `"The language for this worksheet."`, marking could say `"The language the student is writing in."` Same meaning, less templated feel.

- **Bare "Network error. Try again." repeats across 4 files** — `page-lesson-plan.js:202`, `page-worksheet.js:167`, `page-cefr.js:264`, `page-marking.js:223` — universal fallback for fetch failure. Functional, but a tutor who hits one and then a second sees identical strings, which feels less like a real error and more like a templated nothing-burger. Fix: tool-specific micro-variation — lesson-plan: `"Couldn't reach the planner. Try again in a moment."`; worksheet: `"Couldn't reach the worksheet generator. Try again."`; cefr: `"Couldn't reach the assessor. Try again."` etc. Same reassurance level, more grounded.

- **Lesson-plan FAQ rewrite is good but `<em>"the same shape of output"</em> reads italicised twice** — `index.html:396` — the homepage FAQ ends with `"Use Slatework when you need <em>the same shape of output</em> repeatedly."` Italics for emphasis is fine; but the same emphasis pattern repeats in `lesson-plan.html:189` (`"to <em>structure</em> a 60-minute lesson"`) and several other tool-explainer blocks. Em-italics density is creeping toward AI-style emphasis-as-substitute-for-rhythm. Audit pass: cut italics from the homepage FAQ and the tool explainers where the surrounding rhythm carries the weight; keep them only where the contrast is load-bearing.

- **`// loading…` is the only thing the homepage hero says before its data resolves** — `index.html:204` — the live rate preview shows `&mdash;` as the rate and `// loading…` as the platforms cell. For a hero unit the user lands on, that's a thin first-paint impression. The mono-comment `// loading…` voice is on-brand but the dash placeholder for the rate is mute. Fix: while loading, render a short copy hint instead of `&mdash;`, e.g. `<div id="preview-rate" class="preview-rate">// computing…</div>` keyed off the same caption style — visually consistent with the platform cell's mono comment.

- **`'Assess'` is a bare verb without object** — `cefr.html:162` — submit button label `"Assess"`. Surrounding tool buttons read `"Generate plan"`, `"Generate worksheet"`, `"Mark and suggest feedback"`, `"Place the student"` — all verb + object. Bare `"Assess"` reads like a developer label that escaped to UI. Fix: `"Assess writing"` or `"Place from sample"` (matches the rule-based mode's `"Place the student"`).

### Nice-to-have
- **Editor "Cancel — don't save anything" repeats verbatim in tutor + student editors** — `src/lib/profile-ui.js:196,317` — same string both editors. Fine, but the tutor flow is faster (2 fields) than the student flow (8 fields) and the reassurance lands differently. Optional: tutor editor `"Cancel"` (the empty-state caption already says "works without saving"), student editor keeps `"Cancel — don't save anything"`. Net signal-to-noise unchanged, less repetition.

- **"Adjust for today (optional)" is opaque on first read** — `src/lib/profile-ui.js:435` — the expander summary doesn't tell a tutor what they're going to find inside. A first-time visitor opens it expecting "today's date" or similar; what they get is per-lesson level/mode/exam overrides. Fix: `"Adjust this lesson only (optional)"` or `"Override level / mode / exam for this lesson"`. Slightly longer but disambiguated.

- **404 page line reads almost too clipped** — `404.html:37` — `"That URL doesn't match any tool we ship. The slate is clean."` The "slate is clean" line is brand-clever but lands as nothing-was-ever-there which is the wrong feeling for a wrong-URL error. Fix: `"That URL doesn't match any tool we ship. The slate's already wiped — try the toolkit."` or just drop the "slate is clean" sentence and let the CTA carry it.

- **Drop-zone privacy paragraph buries the lede** — `marking.html:157`, `cefr.html:150` — opens with `"<strong>Student names visible in the document?</strong>"` (a question) then explains they're never stored. Stronger as a statement: `"<strong>Student names in the file are never stored by us.</strong>"` then the explanation. Question-as-headline reads slightly clickbaity for a privacy notice.

- **Tool-explainer "Use it when:" sentences sometimes run 35+ words** — `lesson-plan.html:192`, `marking.html:184`, `rates.html:182` — these scenario lines all run long with a semicolon-or-clause structure. They scan, but at this length the brand's short-sentence rhythm breaks. Optional pass: cut to two sentences.

- **About page "It's the second project from..." opens with implicit antecedent** — `about.html:71` — `"Slatework is a small, free toolkit... It's the second project from Authorly..."` — `It's` reads as referring to "toolkit" but actually means "Slatework". Tiny ambiguity. Fix: `"Slatework is the second project from the maker of Authorly..."` (mirrors the homepage's maker block).

## What Slatework does well
- **Privacy frames are doing real work, not boilerplate.** Each AI tool tells the truth about exactly which third party sees what (Anthropic for body, Google Vision for OCR, Pexels for stock keywords) without the legalese trap. The phrase `"the marking model only ever sees text, never the image"` on `marking.html:163` is the kind of specific, technical, reassuring copy almost nobody writes.
- **The "What it isn't." structural conceit.** Every tool-explainer block ends with one. Marking: "Authoritative grading." CEFR: "A placement test for institutional reporting." Contract: "A notarised contract or legal advice." This is *negative-space copywriting* and it's rare in the wild.
- **Modal copy lands warmth without sentiment.** "Optional. Slatework works without saving anything." is doing two jobs (tells you it's optional, tells you the no-save default works fully) in nine words. The matching cancel button "Cancel — don't save anything" is the reassurance landing twice. This is design-by-humans.
- **The error message system in `_lib.js`.** Every error path returns `(ref ${ts})` so a user emailing for help can be debugged. Auth failure carries `"this is on us, not you"` voice. The content-blocked path provides an actionable three-bullet recovery list inline in the error string. This is craft work, not a pattern most products bother with.
- **Voice held across the 3,200-word tool-page expansion.** Adding that much content to 8 thin pages was the moment most tools' brand voice would slip into stuffy SEO copy. It didn't here. The `tool-explainer` blocks read like they were written by the same person on the same afternoon.
